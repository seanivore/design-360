## 4. Narrative spine — Phase C

Phase C = Custom AI Solutions (Modern AI). Copy-only for v4.2 (no entries yet). Slightly longer paragraph because it carries the whole spine alone, and because this is the part that sells.

### Sources

From `v4_1_0_IMPLEMENT.md` § Chronological Timeline Structure:

> **Phase C: Custom AI Solutions (Modern AI)** — These entries showcase modern efforts where I'm using agentic tools to create digital products that businesses need, but then taking things a step further by creating a custom solution that allows the company/client to engage with their current favorite AI model in chat to facilitate the tasks needed to use the digital product that they came to me to create; the goal here is to remove all of the friction and includes things like updating a website or maintaining a social media presence for their growing brand.

From `v4_1_0_IMPLEMENT.md` § Challenges Companies Are Encountering:

> Many companies are finding it incredibly difficult to implement AI because they're trying to do it in the same way they've rolled out most any new technology. They have someone come in to run a seminar, for which they select individuals from each department across the organization to attend. These employees become the leaders of AI integration initiatives and are expected to bring back what they learned and be the go-to "AI guy" on the team who integrates the new tools into everyone's workflow.

> The problem is that AI isn't like other tools, it doesn't work like that. Instead of an organization looking outward for answers, they'd be better off looking inward. Instead of looking to a single person to lead the charge, the organization should be looking to itself to create an AI-driven workflow, because AI is best used when you're using it in a personal context. This implies a more ground-up approach that completely updates old processes.

From `v4_1_0_IMPLEMENT.md` § The AI-Focused Sell, example:

> Custom GPT that walks user through what is needed to update the website store with a new product. The AI then uses a pipeline I created to edit the images, add them to the content network, add all the text it helped you finished to the database, then pushing the site to update.

### Drafted variants

**Variant 1 (paragraph)**
> Most companies are trying to roll out AI the way they roll out any new software: pick a few people from each department, send them to a seminar, expect them to come back as the "AI person" on their team. It doesn't work, because AI isn't that kind of tool. The value isn't in adding it on top of how you already work — it's in rebuilding the work itself.
>
> That's what Phase C is. Custom digital products built agentically against ironed-out dev protocols, then taken one step further: the friction that's *still* left after launch — updating a website, onboarding clients, scheduling content, pushing a new product to a storefront — gets absorbed into a custom AI pipeline the client already uses every day. They open the same ChatGPT they were already using. It asks what changed. It edits the images, writes the copy, updates the database, and pushes the site. No new tool to learn, no Zapier rats-nest to maintain, no new vendor. This portfolio is one example. The Everlastings webstore is another. The DataEdger investment plan and the Thot App are next.

### Recommendation

Ship Variant 1. It's the strongest piece of copy on the page — it absorbs the "looking inward not outward" thesis from the v4_1_0 Challenges section and turns the verbatim Custom GPT example into a vivid one-paragraph demo. The closing roll-call of in-flight projects (Everlastings, DataEdger, Thot App) does the work a featured-entry grid would do once Phase C has entries to link.

## 6. Feature card pattern (the per-tile micro-copy)

Four-card grid, all video tiles, shuffled at runtime from the `featured`-tagged entry pool. The pattern defines what each card emits — actual per-card copy comes from each entry's JSON.

### Sources

No verbatim feature-card copy in `v4_1_0_IMPLEMENT.md`. The Prisma example in that doc described the card structure (icon + title with number + 3–4 checklist items + "Learn more →"), and the strategy section directed that homepage feature copy should "be informed by" the AI-focused sell copy. The v4.2 pattern below is net-new and codifies the structure.

### Drafted variants

**Card emit pattern:**

```
┌─────────────────────────────────┐
│  [feature_video, 4:5 vertical]  │
├─────────────────────────────────┤
│  ## 01                          │  ← shuffle position (01–04)
│  ### {entry.title}              │  ← from JSON title field
│  ✓ {checklist_item_1}           │  ← 2–4 word items from
│  ✓ {checklist_item_2}           │     entry.feature_checklist[]
│  ✓ {checklist_item_3}           │
│  Learn more →                   │  ← /entry.html?slug={slug}
└─────────────────────────────────┘
```

**JSON shape per entry:**

```json
{
  "feature_video": "https://cdn.august.style/media/{slug}/feature-{slug}.mp4",
  "feature_checklist": [
    "Pipeline design",
    "Custom AI integration",
    "Zero-friction handoff"
  ]
}
```

**Checklist patterns by phase:**

- Phase A: *Strategy & process* / *Brand & visual* / *Measured outcomes*
- Phase B: *Generative pipeline* / *Automated publishing* / *On-brand at scale*
- Phase C: *Custom AI flow* / *Embedded in ChatGPT* / *No maintenance overhead*

**"Learn more" alternates:**
1. **Learn more →** (default)
2. See the build →
3. Open the case →
4. Read the work →

**Voice rules:**
- Checklist items: 2–4 words, no verbs required, sentence-case.
- Avoid generic words ("Innovation," "Solutions," "Excellence").

### Recommendation

Ship the pattern as drafted with **"Learn more →"** as the default link label for v4.2 launch. The alternate link labels are worth saving for a later A/B but add per-card variability that hurts scan-ability at launch. The phase-keyed checklist patterns are confident — they map cleanly to the narrative spine and give entry authors a fill-in-the-blank model.
